## Overview

### Design Summary

S7.1 implements a Temporal workflow that manages the lifecycle of write actions (refunds, cancellations, password resets, etc.) from proposal through execution with policy validation, approval routing, and compensation.

**State Machine Flow:**
```
proposed → policy_evaluation → pending_approval → executing → retry → succeeded/failed → compensating
```

**Key Features:**
- All state transitions are durable (survive crashes)
- Queryable via Temporal API (visibility)
- Activity timeouts tailored per action type
- Automatic retry with exponential backoff
- Compensation transactions for multi-step actions
- Complete audit trail for compliance

## State Definitions

### 1. **proposed** (initial)
- Write action created, no side effects yet
- Validate input schema
- Timeout: 5s (inline activity)
- Next: `policy_evaluation`
- On failure: → `failed`

### 2. **policy_evaluation**
- Call OPA policy engine (S7.3)
- Check eligibility, amount limits, escalation thresholds
- Timeout: 30s
- On approve: → `pending_approval`
- On deny: → `failed` (with reason)
- On escalate: → `pending_approval` (manual review required)

### 3. **pending_approval**
- Wait for human approval (Slack/UI)
- Timeout: 4 business hours → escalate to next tier
- Approval inbox tracks state
- Can be rejected → back to `queued` (S7.4)
- Timeout: 86400s (24h, includes escalations)
- Next: `executing` (if approved)

### 4. **executing**
- Call provider API (Stripe, Shopify, etc.)
- Idempotency key ensures at-most-once
- Action-specific timeouts:
  - Refund: 120s
  - Return/RMA: 60s
  - Cancel: 45s
  - Address change: 20s
  - Password reset: 15s
  - Plan change: 90s
- Retry up to 3 times with backoff
- Next: `succeeded` or `retry` or `failed`

### 5. **retry** (intermediate)
- Exponential backoff: 1s, 10s, 60s (max)
- Temporary failure (network, rate limit)
- Max 3 retries per action
- Next: `executing` (retry) or `failed` (exhausted)

### 6. **succeeded** (terminal)
- Action completed successfully
- Record result in audit log
- Emit success event to Kafka
- Trigger post-execution hooks (email, webhooks)
- No further transitions

### 7. **failed** (terminal)
- Action failed after all retries
- Record failure reason
- Emit failure event to Kafka
- Optionally trigger compensation (S7.6)
- No further transitions

### 8. **compensating** (intermediate)
- Multi-step action needs rollback
- Execute compensation activities in reverse order
- Example: refund failed → reverse refund
- Timeout: 30s per compensation
- Next: `failed` (with compensation result)

## Workflow Definition

### ProcessWriteActionWorkflow

```python
@workflow.defn
class ProcessWriteActionWorkflow:
    """
    Temporal workflow for write action orchestration.
    
    State machine:
    proposed → policy_evaluation → pending_approval → executing → succeeded/failed
    
    With retry and compensation paths.
    """
    
    def __init__(self):
        self.state = "proposed"
        self.action = None
        self.audit_trail = []
        self.result = None
    
    @workflow.run
    async def execute(self, action: WriteAction) -> WriteActionResult:
        """Main workflow entry point."""
        
        self.action = action
        self._record_transition("proposed", "policy_evaluation")
        
        # State: policy_evaluation
        policy_decision = await workflow.execute_activity(
            evaluate_policy,
            action,
            ActionContext(...),
            start_to_close_timeout=timedelta(seconds=30),
            retry_policy=RetryPolicy(
                initial_interval=timedelta(seconds=1),
                max_interval=timedelta(seconds=30),
                backoff_coefficient=2,
                max_attempts=2
            )
        )
        
        if not policy_decision.approved:
            self.state = "failed"
            return WriteActionResult(success=False, reason=policy_decision.reason)
        
        # State: pending_approval (if required by policy)
        if policy_decision.escalate or self.action.requires_approval:
            self._record_transition("policy_evaluation", "pending_approval")
            
            approval = await workflow.execute_activity(
                wait_for_approval,
                action.id,
                "agent",
                start_to_close_timeout=timedelta(hours=24),
                schedule_to_close_timeout=timedelta(hours=24)
            )
            
            if not approval.approved:
                self.state = "queued"  # Can be resubmitted
                return WriteActionResult(success=False, reason="Approval rejected")
        
        # State: executing
        self._record_transition("policy_evaluation", "executing")
        
        for attempt in range(3):
            try:
                result = await workflow.execute_activity(
                    execute_provider_action,
                    self.action,
                    self.action.idempotency_key,
                    start_to_close_timeout=self._get_action_timeout(),
                    retry_policy=RetryPolicy(
                        initial_interval=timedelta(seconds=1),
                        max_interval=timedelta(seconds=60),
                        backoff_coefficient=10,
                        max_attempts=3
                    )
                )
                
                if result.success:
                    self.state = "succeeded"
                    self._record_transition("executing", "succeeded")
                    await workflow.execute_activity(
                        emit_event,
                        WriteActionSucceededEvent(action.id, result)
                    )
                    return WriteActionResult(
                        success=True,
                        provider_id=result.provider_id,
                        result=result
                    )
                else:
                    self.state = "retry"
                    self._record_transition("executing", "retry")
            
            except ApplicationFailureException as e:
                if attempt < 2:
                    self.state = "retry"
                    self._record_transition("executing", "retry")
                    # Exponential backoff handled by Temporal
                else:
                    self.state = "failed"
                    self._record_transition("executing", "failed")
                    return WriteActionResult(success=False, reason=str(e))
        
        self.state = "failed"
        return WriteActionResult(success=False, reason="Max retries exceeded")
    
    def _record_transition(self, from_state: str, to_state: str):
        """Record state transition in audit trail."""
        self.audit_trail.append({
            "from": from_state,
            "to": to_state,
            "timestamp": datetime.now(),
            "details": {}
        })
    
    def _get_action_timeout(self) -> timedelta:
        """Get timeout for current action type."""
        timeouts = {
            "refund": 120,
            "return": 60,
            "cancel": 45,
            "address_change": 20,
            "password_reset": 15,
            "plan_change": 90
        }
        return timedelta(seconds=timeouts.get(self.action.action_type, 60))
```

## Crash Recovery

### Deterministic Workflow Execution

- **No direct I/O**: All calls are activities
- **Deterministic replay**: Temporal replays from event history
- **Idempotency via Temporal**: Activities with same input are deduplicated
- **State persistence**: Workflow state serialized at each step
- **Resume from checkpoint**: On crash, resume from last completed activity

### Example: Worker Crash During Execution

```
Timeline:
1. 13:00:00 - proposed → policy_evaluation (activity completes)
2. 13:00:05 - pending_approval (waiting for approval)
3. 13:02:30 - Approval received, → executing
4. 13:02:31 - execute_provider_action activity starts
5. 13:02:45 - CRASH: Worker dies
6. 13:03:00 - New worker starts, resumes workflow
7. 13:03:01 - Replay: re-executes activities 1–3 (from history, no side effects)
8. 13:03:05 - At activity 4: workflow resumes where it left off
9. 13:03:06 - Provider result already recorded in history
10. 13:03:07 - Transitions to succeeded, emits event
```
