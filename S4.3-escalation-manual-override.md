# S4.3 — Escalation & Manual Override

## Overview

The AI triage agent autonomously routes incoming support requests to appropriate channels or queues. However, no triage system is universally confident—complex cases, edge scenarios, or safety concerns require human judgment. Sprint 4.3 implements three critical mechanisms:

1. **Escalation triggers**: conditions that automatically route conversations to human agents
2. **Manual override capability**: human agents can change AI decisions and provide structured feedback
3. **Feedback loop integration**: override reasons feed directly into the S3.8 learning pipeline, closing the loop between operations and model improvement

This sprint extends S3.x (Core Triage Engine) and S3.8 (Learning Pipeline) to operationalize human-in-the-loop workflows at scale.

## Technical Specification

### Escalation Triggers

#### 1. Confidence-Based Escalation
The triage engine assigns a confidence score to each decision (0.0–1.0). If the score falls below a configurable threshold, the conversation escalates immediately.

**Formula:**
```
confidence_score = P(intent | text_features)
escalate_if_confidence < ESCALATION_CONFIDENCE_THRESHOLD[intent_category]
```

**Thresholds by intent category** (tuned per tenant):
- Billing/Account: 0.75 (higher bar—financial impact)
- Technical Troubleshooting: 0.65 (moderate—solvable by KB)
- General Inquiry: 0.55 (lower bar—often self-service)
- Complaint/Escalation: 0.80 (highest—reputational risk)

#### 2. Safety Signals
Independent of confidence, certain content patterns trigger mandatory escalation:

**PII Detection (regex + fuzzy match):**
- Credit card patterns: `\b(?:\d{4}[-\s]?){3}\d{4}\b`
- Social Security Number: `\b\d{3}-\d{2}-\d{4}\b`
- Phone number in message: `\b(?:\+1[-.\s]?)?\(?[0-9]{3}\)?[-.\s]?[0-9]{3}[-.\s]?[0-9]{4}\b`
- Personally identifiable names + account context (ML classifier)

**Policy Violations:**
- Threats or abuse keywords: `["threat", "harm", "violence", "lawsuit", "lawyer"]` (case-insensitive)
- Regulatory keywords: `["GDPR", "HIPAA", "CCPA", "compliance", "audit"]`
- Refund demand + account inactive > 30 days

**Legal Keywords:**
- `["lawsuit", "attorney", "legal action", "court", "arbitration", "class action"]`

**Implementation:** Safety scanner runs asynchronously in a background worker. Triage response is not blocked; if safety flag is set, escalation record is created immediately post-triage.

#### 3. Knowledge Gap
The triage engine maintains a KB coverage index. If no matching resolution or FAQ is found after intent classification:

```
kb_coverage_score = max(similarity_score for r in relevant_resolutions)
escalate_if kb_coverage_score < KB_COVERAGE_THRESHOLD (default: 0.40)
```

Also escalate if:
- Intent marked as `out_of_domain` or `unclassified`
- Required context missing (e.g., conversation metadata needed but unavailable)
- Triage engine returns no suggested next action

#### 4. Customer Sentiment
Real-time sentiment analysis on customer messages. If anger or frustration score exceeds threshold, escalate to specialized team:

```
sentiment_scores = model_predict(customer_message)
anger_score = sentiment_scores.anger
frustration_score = sentiment_scores.frustration

escalate_if (anger_score > 0.75) or (frustration_score > 0.70)
```

Sentiment model: fine-tuned BERT classifier trained on support chat labeled data (S2.1).

### Manual Override

**User story:** A human agent views a triage decision and disagrees. They override it, selecting a reason code and optionally adding a note.

**Workflow:**
1. Agent UI displays current triage decision (intent, confidence, suggested action)
2. Agent clicks "Override" button
3. Modal appears with:
   - Dropdown: override reason code (enum, 15–20 options)
   - Text field: optional free-text note (max 500 chars)
   - Preview: original decision vs. new decision (if changing route)
4. Agent submits override
5. System:
   - Appends to immutable audit log (hash-chained)
   - Updates escalation record status to `overridden`
   - Dispatches feedback signal to S3.8 learning pipeline

**Override reason codes** (OverrideReasonCode enum):
- `CONFIDENCE_TOO_LOW`: Agent trusts their judgment over low-confidence triage
- `CONTEXT_MISSING`: Triage missed conversation context
- `SENTIMENT_MISCLASSIFIED`: Sentiment analysis was wrong
- `INTENT_MISCLASSIFIED`: Wrong intent category assigned
- `POLICY_OVERRIDE`: Business logic override (e.g., VIP customer gets priority)
- `SAFETY_FALSE_POSITIVE`: Escalation triggered but no safety issue present
- `CUSTOMER_PREFERENCE`: Customer explicitly requested a different path
- `ROUTING_ERROR`: Triage routed to wrong queue/agent
- `FEATURE_REQUEST_QUALIFIED`: Escalation recognized as genuine feature request
- `DUPLICATE_TICKET`: Duplicate of existing ticket (KB miss)
- `REQUIRES_INVESTIGATION`: Needs manual investigation not available to AI
- `BUSINESS_DECISION`: Override for strategic/account management reasons
- `DATA_QUALITY_ISSUE`: Malformed input caused incorrect triage
- `THIRD_PARTY_INTEGRATION`: Requires external service not in triage domain
- `OTHER`: Reason not listed above (requires note)

## Implementation

### Confidence Gate (Python pseudocode)

```python
def should_escalate_low_confidence(triage_output: dict, tenant_config: dict) -> bool:
    """Check if confidence score falls below tenant-specific threshold."""
    intent_category = triage_output.get("intent_category")
    confidence_score = triage_output.get("confidence", 0.0)
    
    # Get threshold for this intent category
    threshold = tenant_config.get(
        f"ESCALATION_CONFIDENCE_THRESHOLD_{intent_category}",
        default=tenant_config.get("ESCALATION_CONFIDENCE_THRESHOLD_DEFAULT", 0.65)
    )
    
    if confidence_score < threshold:
        return True, {
            "reason": "confidence_below_threshold",
            "threshold": threshold,
            "actual_confidence": confidence_score
        }
    return False, {}
```

### Safety Scanner (async, non-blocking)

```python
# tasks.py (Celery)
@app.task(bind=True, max_retries=2)
def scan_conversation_for_safety_signals(self, conversation_id: str, tenant_id: str):
    """Scan conversation for PII, policy violations, legal keywords."""
    conversation = get_conversation(conversation_id)
    signals = []
    
    # PII regex check
    pii_patterns = {
        "credit_card": r"\b(?:\d{4}[-\s]?){3}\d{4}\b",
        "ssn": r"\b\d{3}-\d{2}-\d{4}\b",
        "phone": r"\b(?:\+1[-.\s]?)?\(?[0-9]{3}\)?[-.\s]?[0-9]{3}[-.\s]?[0-9]{4}\b"
    }
    for pii_type, pattern in pii_patterns.items():
        if re.search(pattern, conversation.text):
            signals.append({"type": "pii_detected", "pii_type": pii_type})
    
    # ML classifier for PII (fuzzy matching on named entities)
    entities = extract_named_entities(conversation.text)
    if has_personally_identifiable_name(entities):
        signals.append({"type": "pii_detected", "pii_type": "named_entity"})
    
    # Policy violation keywords
    threat_keywords = ["threat", "harm", "violence", "lawsuit", "lawyer"]
    if any(keyword in conversation.text.lower() for keyword in threat_keywords):
        signals.append({"type": "policy_violation", "violation_type": "threat"})
    
    # Legal keywords
    legal_keywords = ["lawsuit", "attorney", "legal action", "court", "arbitration"]
    if any(keyword in conversation.text.lower() for keyword in legal_keywords):
        signals.append({"type": "legal_keyword_detected"})
    
    # Store signals
    if signals:
        escalation = EscalationRecord.create(
            conversation_id=conversation_id,
            tenant_id=tenant_id,
            trigger_type="safety_signal",
            safety_flags=signals,
            status="pending"
        )
    
    return {"escalation_created": len(signals) > 0, "signals": signals}
```

### Immutable Audit Log (Hash Chain)

```python
class AuditLog:
    @staticmethod
    def create_override_entry(override: ManualOverride) -> str:
        """Create audit log entry with hash chain to previous."""
        prev_entry = AuditLog.get_latest_for_escalation(override.escalation_id)
        prev_hash = prev_entry.hash if prev_entry else "0000000000000000"
        
        # Create deterministic payload
        entry_data = {
            "override_id": override.id,
            "escalation_id": override.escalation_id,
            "agent_id": override.agent_id,
            "reason_code": override.reason_code,
            "timestamp": override.overridden_at.isoformat(),
            "prev_hash": prev_hash
        }
        
        # Compute SHA256 hash
        entry_json = json.dumps(entry_data, sort_keys=True)
        entry_hash = hashlib.sha256(entry_json.encode()).hexdigest()
        
        # Persist
        audit_entry = AuditLogEntry(
            override_id=override.id,
            data=entry_json,
            hash=entry_hash,
            prev_hash=prev_hash
        )
        audit_entry.save()
        
        return entry_hash
    
    @staticmethod
    def verify_chain(escalation_id: str) -> bool:
        """Verify integrity of audit log chain (all hashes valid)."""
        entries = AuditLogEntry.filter(escalation_id=escalation_id).order_by("created_at")
        
        prev_hash = "0000000000000000"
        for entry in entries:
            if entry.prev_hash != prev_hash:
                return False  # Chain broken
            prev_hash = entry.hash
        
        return True
```

### Feedback Dispatch to Learning Pipeline

```python
# tasks.py (Celery)
@app.task(bind=True, max_retries=3)
def dispatch_feedback_signal(self, override_id: str):
    """Create and dispatch feedback signal to S3.8 learning pipeline."""
    override = ManualOverride.get(override_id)
    escalation = EscalationRecord.get(override.escalation_id)
    conversation = Conversation.get(escalation.conversation_id)
    
    feedback_signal = FeedbackSignal(
        override_id=override_id,
        signal_type="intent_correction",  # or "confidence_adjustment", etc.
        tenant_id=escalation.tenant_id,
        payload={
            "original_input": {
                "customer_message": conversation.last_message(),
                "metadata": {"user_id": conversation.user_id, ...}
            },
            "triage_output": escalation.original_triage_output,
            "override_output": override.override_decision,
            "override_reason": override.reason_code,
            "agent_note": override.note,
            "agent_id": override.agent_id
        },
        dispatched_at=now()
    )
    feedback_signal.save()
    
    # POST to learning pipeline webhook
    webhook_url = settings.FEEDBACK_WEBHOOK_URL
    try:
        response = requests.post(
            webhook_url,
            json=feedback_signal.to_dict(),
            timeout=10,
            headers={"Authorization": f"Bearer {settings.WEBHOOK_AUTH_TOKEN}"}
        )
        if response.status_code == 202:
            feedback_signal.processing_status = "queued"
            feedback_signal.save()
    except RequestException as exc:
        # Retry with exponential backoff
        raise self.retry(exc=exc, countdown=60 * (2 ** self.request.retries))
```

## Summary

Sprint 4.3 operationalizes human oversight of AI triage decisions through:

1. **Four escalation triggers** (confidence, safety, knowledge gap, sentiment) ensuring complex or risky cases reach human agents
2. **Structured override capability** with reason codes, enabling agents to correct AI decisions while providing feedback
3. **Immutable audit trail** (hash-chained records) ensuring compliance and traceability
4. **Closed feedback loop** to S3.8 learning pipeline, turning human corrections into training signals for model improvement

This completes the human-in-the-loop infrastructure for a production-grade support triage platform.
