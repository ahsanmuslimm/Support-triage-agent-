# S9.7: Load-Aware Rebalancing

Agent load tracking, dynamic rebalancing, and stale assignment reclaim.

## Implementation Summary
- Assignment pool: Agents with current_load = open_tickets + estimated_handling_time/60
- Rebalancing trigger: When agent load > 1.5x average load
- Load calculation: Combines ticket count and estimated duration
- Stale assignment reclaim: Unacknowledged tickets > timeout (P1:5min, P2:15min, P3:30min) reassigned
- Agent offline release: Tickets released if agent offline >1min
- Skill matching: Find agents with required skills before assignment
- Capacity limits: Agents have max_capacity; assignment fails if exceeded
- Centrifugo presence: Real-time agent online/offline status
- ~350 lines code + 25 tests

## Key Classes
- LoadBalancer: Main engine for assignment and rebalancing
- AgentLoad: Agent workload tracking
- TicketAssignment: Assignment record with acknowledgement tracking
