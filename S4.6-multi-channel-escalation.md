# S4.6 — Multi-Channel Escalation

## Overview

Route escalation notifications across Slack, email, PagerDuty, and webhook to ensure rapid incident response and seamless on-call handoff. This sprint delivers a templated, multi-channel notification dispatcher with on-call rotation integration, Do-Not-Disturb scheduling, and per-tenant routing configuration. Escalations respect priority tiers, with configurable delivery channels and delivery logging for audit trails.

---

## Technical Specification

### Four Notification Channels

#### 1. Slack
- **Workspace/channel routing**: Tenant-configurable workspace token and channel ID per priority tier
- **Block Kit format**: Rich, interactive message layout with incident summary, suggested actions, and metadata
- **Interactive buttons**: Native Slack blocks for Acknowledge, Assign, Snooze (5/15/60 min), and View Details actions
- **Payload webhook**: Stateless button interactions validated via Slack signature verification (HMAC-SHA256)
- **Rate limit handling**: Respect 1 msg/sec per channel; queue and backoff with exponential retry

#### 2. Email
- **SMTP/SendGrid integration**: Choose transport via config; SendGrid recommended for enterprise deployments
- **HTML templates**: Jinja2-templated, responsive design; branded header/footer per tenant
- **Priority prefix**: Subject line includes `[P0]`, `[P1]`, etc. for client-side filtering
- **Distribution**: To/CC/BCC support; route to on-call agent + fallback recipients (team lead, escalation alias)
- **Rate limiting**: Respect SendGrid's 100 req/sec; batch within window

#### 3. PagerDuty
- **Events API v2**: Direct HTTPS POST to `events.pagerduty.com/v2/enqueue` with dedup keys
- **Severity mapping**: P0 → `critical`, P1 → `error`, P2 → `warning`, P3 → `info`
- **Incident creation**: Auto-create or update existing incident by dedup key; respects PagerDuty rate limits (60 req/min per account)
- **Linked services**: Attach context URL (link to triage dashboard) in event details
- **On-call resolution**: Query schedules API to resolve current on-call agent before dispatch

#### 4. Webhook
- **Generic HTTP POST**: Configurable endpoint per tenant/priority; flexible payload schema
- **Custom headers**: Authorization header, custom metadata headers (X-Tenant-ID, X-Priority, X-Escalation-ID)
- **HMAC signature**: SHA256(body + secret) in `X-Signature` header for authenticity verification
- **Retry logic**: 3 retries on 5xx or timeout, exponential backoff; log all attempts with response status

## Implementation

### Channel Dispatcher (Strategy Pattern)

Base dispatcher interface with concrete implementations per channel:

```python
class ChannelDispatcher(ABC):
    @abstractmethod
    async def dispatch(self, escalation: Escalation, config: ChannelRoutingConfig) -> DispatchResult:
        pass

class SlackDispatcher(ChannelDispatcher):
    async def dispatch(self, escalation: Escalation, config: ChannelRoutingConfig) -> DispatchResult:
        # Render Slack blocks, resolve on-call, post message, log delivery

class EmailDispatcher(ChannelDispatcher):
    async def dispatch(self, escalation: Escalation, config: ChannelRoutingConfig) -> DispatchResult:
        # Render HTML template, resolve on-call, send via SMTP/SendGrid, log

class PagerDutyDispatcher(ChannelDispatcher):
    async def dispatch(self, escalation: Escalation, config: ChannelRoutingConfig) -> DispatchResult:
        # Fetch on-call, map priority to severity, POST to Events API v2, log

class WebhookDispatcher(ChannelDispatcher):
    async def dispatch(self, escalation: Escalation, config: ChannelRoutingConfig) -> DispatchResult:
        # Sign payload, POST with custom headers, retry on failure, log
```

### DND Logic (Time-Window Boundary Conditions)

```python
class DNDChecker:
    def is_in_dnd(self, agent_id: str, dnd_schedule: DNDSchedule, 
                  current_time: datetime = None) -> bool:
        if not current_time:
            current_time = datetime.now()
        
        # Convert to agent's timezone
        tz = pytz.timezone(dnd_schedule.timezone)
        local_time = current_time.astimezone(tz)
        
        # Check day of week
        day_name = local_time.strftime('%A').lower()
        if day_name not in dnd_schedule.days_of_week:
            return False
        
        # Parse times as datetime.time objects
        start = datetime.strptime(dnd_schedule.start_time, '%H:%M').time()
        end = datetime.strptime(dnd_schedule.end_time, '%H:%M').time()
        current = local_time.time()
        
        # Handle overnight spans (e.g., 18:00 to 09:00)
        if start <= end:
            return start <= current <= end
        else:
            return current >= start or current <= end
```

### Rate Limiting Implementation
```python
class RateLimiter:
    def __init__(self, channel_type: str, limit_per_window: int, window_seconds: int):
        self.channel_type = channel_type
        self.limit = limit_per_window
        self.window = window_seconds
        self.tokens = deque()

    async def acquire(self) -> bool:
        now = time.time()
        # Remove expired tokens
        while self.tokens and self.tokens[0] + self.window < now:
            self.tokens.popleft()
        
        if len(self.tokens) < self.limit:
            self.tokens.append(now)
            return True
        return False
```
