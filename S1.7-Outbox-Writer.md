# S1.7 — Outbox Writer

**Sprint:** 1 (Ingestion & Conversation Core)  
**Deliverable:** Transactional outbox pattern for event durability  
**Effort:** 1 day  
**Dependencies:** S0 (PostgreSQL, background tasks), S1.2 (Message ingestion)

---

## Overview

The transactional outbox pattern ensures **zero message loss** during async processing:

1. Message ingested → persisted in `messages` table
2. Event created in `outbox` table (same transaction)
3. Poller reads outbox → publishes to downstream workers (Triage, Enrichment, etc.)
4. Events marked as processed only after successful publication
5. Orphaned events retried (eventual consistency)

This eliminates the risk of **message loss** if message is persisted but event is never published to worker queue.

---

## Technical Specification

### 1. Outbox Pattern Overview

**Traditional (risky):**
```
1. Persist message → DB
2. Publish event → Kafka
   [If step 2 fails, event lost]
```

**Transactional Outbox (safe):**
```
Transaction {
  1. Persist message → DB
  2. Insert event → outbox table (same txn)
}
[If entire txn fails, both roll back]

Separate process:
1. Poller reads outbox (status = pending)
2. Publish event → Kafka / queue
3. Update outbox (status = processed)
```

### 2. Outbox Schema

```sql
CREATE TABLE outbox (
    id BIGSERIAL PRIMARY KEY,
    tenant_id BIGINT NOT NULL REFERENCES tenants(id),
    conversation_id BIGINT NOT NULL REFERENCES conversations(id),
    event_type VARCHAR(50) NOT NULL,           -- 'message_ingested', 'conversation_created', etc.
    aggregate_id BIGINT,                       -- ID of the aggregate (message_id, etc.)
    payload JSONB NOT NULL,                    -- Event data
    status VARCHAR(50) NOT NULL DEFAULT 'pending',  -- 'pending', 'processing', 'processed', 'dead_letter'
    error_message TEXT,                        -- If failed, why?
    retry_count INTEGER DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    processed_at TIMESTAMP,
    next_retry_at TIMESTAMP,
    CONSTRAINT status_check CHECK (status IN ('pending', 'processing', 'processed', 'dead_letter'))
);

CREATE INDEX idx_outbox_pending ON outbox(tenant_id, status) WHERE status IN ('pending', 'processing');
CREATE INDEX idx_outbox_retry ON outbox(tenant_id, next_retry_at) WHERE status IN ('pending', 'processing');
```

### 4. Outbox Writer

```python
class OutboxWriter:
    def __init__(self, db_session):
        self.db = db_session
    
    async def write_event(
        self,
        tenant_id: int,
        conversation_id: int,
        event_type: str,
        aggregate_id: int,
        payload: dict,
    ) -> int:
        """
        Write event to outbox (within transaction).
        
        Must be called within same transaction as the triggering action.
        """
        
        result = await self.db.execute("""
            INSERT INTO outbox (tenant_id, conversation_id, event_type, aggregate_id, payload, status, created_at)
            VALUES ($1, $2, $3, $4, $5, $6, $7)
            RETURNING id
        """, tenant_id, conversation_id, event_type, aggregate_id, json.dumps(payload), 'pending', datetime.utcnow())
        
        return result.scalar()
```

### 5. Integration with Message Ingestion

**FastAPI Endpoint (S1.2):**

```python
@app.post("/v1/conversations/{conversation_id}/messages")
async def ingest_message(
    conversation_id: str,
    request: IngestMessageRequest,
    db: AsyncSession = Depends(get_db),
    tenant_id: int = Depends(require_tenant),
) -> dict:
    """Ingest message (S1.2) with transactional outbox."""
    
    try:
        # Start transaction
        async with db.begin():
            # 1. Persist message
            message = Message(
                conversation_id=conversation_id,
                channel=request.channel,
                body=request.body,
                from_address=request.from_address,
                created_at=datetime.utcnow(),
                tenant_id=tenant_id,
            )
            db.add(message)
            await db.flush()  # Generate message.id
            
            # 2. Write outbox event (same transaction)
            outbox_writer = OutboxWriter(db)
            await outbox_writer.write_event(
                tenant_id=tenant_id,
                conversation_id=conversation_id,
                event_type="message_ingested",
                aggregate_id=message.id,
                payload={
                    "message_id": message.id,
                    "conversation_id": conversation_id,
                    "channel": request.channel,
                    "created_at": message.created_at.isoformat(),
                }
            )
            
            # Transaction commits here (both message and outbox)
    
    except Exception as e:
        # Transaction rolls back, no message or outbox entry
        logger.error(f"Message ingestion failed: {e}")
        raise HTTPException(status_code=500, detail="Ingest failed")
    
    # Return 202 Accepted with stream URL
    return {
        "status": "accepted",
        "conversation_id": conversation_id,
        "stream_url": f"/v1/streams/conversations/{conversation_id}"
    }
```

### 6. Outbox Poller

Background task that reads outbox and publishes events:

```python
class OutboxPoller:
    def __init__(self, db_session, publisher, max_batch_size: int = 100):
        self.db = db_session
        self.publisher = publisher  # Kafka, RabbitMQ, HTTP, etc.
        self.max_batch_size = max_batch_size
        self.max_retries = 3
    
    async def poll_once(self) -> dict:
        """Poll outbox once and process pending events."""
        
        result = {
            "polled_at": datetime.utcnow().isoformat(),
            "processed": 0,
            "failed": 0,
            "retried": 0,
        }
        
        # Read pending events (ordered by created_at for fairness)
        pending = await self.db.query("""
            SELECT id, tenant_id, conversation_id, event_type, aggregate_id, payload, retry_count
            FROM outbox
            WHERE status IN ('pending', 'processing')
            AND (next_retry_at IS NULL OR next_retry_at <= NOW())
            ORDER BY created_at ASC
            LIMIT $1
        """, self.max_batch_size).all()
        
        for event in pending:
            try:
                # Mark as processing (atomic compare-and-set)
                updated = await self.db.execute("""
                    UPDATE outbox
                    SET status = 'processing'
                    WHERE id = $1 AND status IN ('pending', 'processing')
                    RETURNING id
                """, event.id)
                
                if not updated:
                    continue  # Already processing by another poller
                
                # Publish event
                await self.publisher.publish(
                    topic=f"triage.{event.event_type}",
                    message={
                        "event_id": event.id,
                        "tenant_id": event.tenant_id,
                        "conversation_id": event.conversation_id,
                        "event_type": event.event_type,
                        "aggregate_id": event.aggregate_id,
                        "payload": event.payload,
                        "published_at": datetime.utcnow().isoformat(),
                    }
                )
                
                # Mark as processed
                await self.db.execute("""
                    UPDATE outbox
                    SET status = 'processed', processed_at = NOW()
                    WHERE id = $1
                """, event.id)
                
                result["processed"] += 1
                
            except Exception as e:
                # Retry logic
                retry_count = event.retry_count + 1
                
                if retry_count >= self.max_retries:
                    # Move to dead letter
                    await self.db.execute("""
                        UPDATE outbox
                        SET status = 'dead_letter', error_message = $1, retry_count = $2
                        WHERE id = $3
                    """, str(e)[:500], retry_count, event.id)
                    
                    result["failed"] += 1
                    
                    # Log for manual inspection
                    logger.error(f"Event {event.id} moved to DLQ: {e}")
                else:
                    # Schedule retry (exponential backoff: 2^retry seconds)
                    backoff_seconds = 2 ** retry_count
                    next_retry = datetime.utcnow() + timedelta(seconds=backoff_seconds)
                    
                    await self.db.execute("""
                        UPDATE outbox
                        SET status = 'pending', retry_count = $1, next_retry_at = $2, error_message = $3
                        WHERE id = $4
                    """, retry_count, next_retry, str(e)[:500], event.id)
                    
                    result["retried"] += 1
        
        return result
    
    async def start_polling(self, interval_seconds: int = 5):
        """Start continuous polling."""
        
        while True:
            try:
                result = await self.poll_once()
                logger.info(f"Outbox poll: {result}")
            except Exception as e:
                logger.error(f"Outbox poll error: {e}")
            
            await asyncio.sleep(interval_seconds)
```

### 7. Publisher Interface

Support multiple publishers (Kafka, RabbitMQ, HTTP webhook, in-memory queue):

```python
class Publisher(ABC):
    @abstractmethod
    async def publish(self, topic: str, message: dict) -> str:
        """Publish message, return message_id."""
        pass

class KafkaPublisher(Publisher):
    def __init__(self, bootstrap_servers: str):
        self.producer = AIOKafkaProducer(bootstrap_servers=bootstrap_servers)
    
    async def publish(self, topic: str, message: dict) -> str:
        result = await self.producer.send_and_wait(
            topic,
            value=json.dumps(message).encode()
        )
        return result.offset

class HTTPPublisher(Publisher):
    def __init__(self, worker_url: str):
        self.worker_url = worker_url
    
    async def publish(self, topic: str, message: dict) -> str:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                f"{self.worker_url}/events",
                json=message,
                timeout=aiohttp.ClientTimeout(total=10)
            ) as resp:
                if resp.status == 202:
                    return message.get("event_id")
                else:
                    raise HTTPException(resp.status, await resp.text())

class InMemoryPublisher(Publisher):
    """For testing / MVP."""
    def __init__(self):
        self.messages = []
    
    async def publish(self, topic: str, message: dict) -> str:
        message["topic"] = topic
        self.messages.append(message)
        return str(uuid.uuid4())
```

### 8. Dead Letter Handling

Events that fail max retries go to dead letter queue:

```sql
CREATE TABLE outbox_dlq (
    id BIGSERIAL PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    outbox_id BIGINT NOT NULL REFERENCES outbox(id),
    event_type VARCHAR(50) NOT NULL,
    error_message TEXT,
    last_error_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    manual_retry_requested BOOLEAN DEFAULT FALSE,
    retried_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**Dashboard:**
- Show DLQ events
- Manual retry button (resets status to 'pending', reset retry_count)
- Alert when DLQ size > threshold
