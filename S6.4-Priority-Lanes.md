## Overview

### What This Delivers

S6.4 implements message routing with SLA-based priority:

**Problem**: All messages FIFO, but chat urgency (1-min SLA) != email (8-hour SLA)
**Solution**: Two priority queues with dedicated worker pools

**Before**: Email message at 9:00am blocks chat message at 9:00:01am (1 hour delay!)
**After**: Chat processed immediately (1 min), email batched (8-hour window)

**Key Artifacts**:
- `services/api/src/triage/adapters/priority_queue.py` - Redis-backed priority queues
- `services/api/src/triage/adapters/worker_pool.py` - Worker pool manager (framework)
- `services/api/src/triage/adapters/event_consumer.py` - Consumer with priority routing
- `services/api/tests/test_adapters_kafka.py` - Priority queue unit tests

### Design Principles

1. **Two Lanes**:
   - Chat/Web: 10 workers, 1-min SLA (urgent)
   - Email: 3 workers, 8-hour SLA (batch)

2. **Within-Lane FIFO**: Messages in same priority ordered by arrival time
3. **Between-Lane Priority**: Chat never waits for email
4. **Starvation Prevention**: Email processed when chat queue empty
5. **Redis Sorted Sets**: Score = priority (channel) + timestamp (FIFO within priority)

## Architecture

### Channel Priority Enum

```python
class Channel(IntEnum):
    VOICE = 0      # Future: highest priority (reserved)
    CHAT = 1       # 1-min SLA (urgent)
    WEB = 2        # 2-min SLA (high)
    EMAIL = 10     # 8-hour SLA (low)
```

**Lower number = higher priority**: Chat (1) always processed before Email (10)

### Queue Topology

```
Incoming Message
    ↓
Classify channel (email, chat, web)
    ↓
Determine priority & SLA:
  - chat/web → Chat Lane (10 workers)
  - email    → Email Lane (3 workers)
    ↓
Enqueue to Redis sorted set:
  - Queue key: "queue:chat" or "queue:email"
  - Score: priority + timestamp (ensures FIFO within priority)
    ↓
Worker pools dequeue and process
```

### Redis Sorted Sets

```
queue:chat (sorted by score = priority + arrival_time)
  Score: 1.001000  Item: {"message_id": "msg_1", "channel": "chat", ...}
  Score: 1.001500  Item: {"message_id": "msg_2", "channel": "chat", ...}

queue:email (sorted by score)
  Score: 10.002000  Item: {"message_id": "msg_3", "channel": "email", ...}
  Score: 10.003000  Item: {"message_id": "msg_4", "channel": "email", ...}
```

**Score Calculation**:
```python
score = priority_channel + (timestamp / 1e6)
# Example: Channel.CHAT (1) + 1.001000 = 1.001000
# Example: Channel.EMAIL (10) + 10.002000 = 10.002000
# Dequeue: ZRANGE queue_key 0 0 → gets lowest score first
#          Returns msg_1 (score 1.001000) before msg_3 (score 10.002000)
```

## Implementation

### PriorityQueue (priority_queue.py)

```python
class PriorityQueue:
    async def enqueue_message(
        self,
        message_id: str,
        tenant_id: str,
        channel: str,
        payload: Dict[str, Any],
    ) -> str:
        """Enqueue message to appropriate lane."""
        
        # Determine priority
        priority_channel = Channel[channel.upper()]
        
        # Select queue based on priority
        if priority_channel in (Channel.CHAT, Channel.WEB):
            queue_key = "queue:chat"
            workers = 10
        else:  # EMAIL, unknown
            queue_key = "queue:email"
            workers = 3
        
        # Calculate score: priority + timestamp
        score = float(priority_channel) + (datetime.utcnow().timestamp() / 1e6)
        
        # Serialize message
        item = {
            "message_id": message_id,
            "tenant_id": tenant_id,
            "channel": channel,
            "payload": payload,
            "enqueued_at": datetime.utcnow().isoformat(),
        }
        
        # Add to sorted set (Redis ZADD)
        await self.redis.zadd(queue_key, {json.dumps(item): score})
        
        return queue_key
    
    async def dequeue_message(
        self,
        channel: str,
        batch_size: int = 1,
    ) -> List[Dict[str, Any]]:
        """Dequeue message(s) from lane (lowest score first = highest priority)."""
        
        queue_key = "queue:chat" if channel == "chat" else "queue:email"
        
        # Get lowest-scored items
        items = await self.redis.zrange(queue_key, 0, batch_size - 1)
        
        if items:
            await self.redis.zrem(queue_key, *items)
        
        return [json.loads(item) for item in items]
    
    async def get_queue_depth(self, channel: str) -> int:
        """Get queue depth (for monitoring)."""
        queue_key = "queue:chat" if channel == "chat" else "queue:email"
        return await self.redis.zcard(queue_key)
    
    async def get_queue_stats(self) -> Dict[str, Any]:
        """Get stats for both queues."""
        return {
            "chat": {
                "depth": await self.get_queue_depth("chat"),
                "workers": 10,
                "sla_mins": 1,
            },
            "email": {
                "depth": await self.get_queue_depth("email"),
                "workers": 3,
                "sla_hours": 8,
            },
        }
```

## Worker Pool Framework

(Documented in design; actual WorkerPool implementation in separate module)

```python
class WorkerPool:
    """Fixed-size pool of workers consuming from priority queue."""
    
    async def start(self) -> None:
        """Start num_workers concurrent tasks."""
        for i in range(self.num_workers):
            task = asyncio.create_task(self._worker_loop(worker_id=i))
            self._tasks.append(task)
    
    async def _worker_loop(self, worker_id: int) -> None:
        """Single worker: dequeue → process → repeat."""
        while not self._stop:
            messages = await self.priority_queue.dequeue_message(
                channel=self.channel,
                batch_size=1,
            )
            if messages:
                await self.handler_func(messages[0])
            else:
                await asyncio.sleep(0.1)  # Backoff if queue empty
```

## Scenarios

### Scenario 1: Chat Always Processed First

```
Timeline:
09:00:00 - Email message arrives → Enqueued (queue:email, score=10.0001)
09:00:01 - Chat message arrives  → Enqueued (queue:chat, score=1.0001)

Workers dequeue (lowest score first):
- Chat worker: Dequeues score=1.0001 (processed at 09:00:02)
- Email worker: Dequeues score=10.0001 (processed at 09:00:30, not blocked)

Result: Chat processed ~1 second later, Email processed when worker available
No blocking between lanes ✓
```

### Scenario 2: Within-Priority FIFO

```
Timeline:
09:00:00 - Chat msg_1 arrives → Queue (score=1.001000)
09:00:01 - Chat msg_2 arrives → Queue (score=1.001001)
09:00:02 - Chat msg_3 arrives → Queue (score=1.001002)

Dequeue order (lowest score first):
1. msg_1 (score=1.001000)
2. msg_2 (score=1.001001)
3. msg_3 (score=1.001002)

Result: FIFO within same priority ✓
```

### Scenario 3: Starvation Prevention

```
High email volume (100+ messages), 3 email workers busy.
But chat queue empty: Email workers available for other work.

Configuration ensures:
- Chat lane never waits for email (separate worker pools)
- Email processed whenever chat queue empty
- No forced starvation ✓
```

## FAQ

**Q: What if we need 3 lanes (chat, email, SMS)?**  
A: Extend Channel enum and add queue per lane. Same pattern applies.

**Q: Can we dynamically adjust worker counts?**  
A: Yes. Modify CHAT_WORKERS and restart workers. Graceful shutdown before scaling.

**Q: What if chat queue grows faster than we can process?**  
A: Increase CHAT_WORKERS or adjust SLA. Monitor p99 latency for capacity planning.

**Q: Is Redis sorted set performance good enough?**  
A: Yes. ZADD and ZRANGE are O(log N), fast for millions of messages.
