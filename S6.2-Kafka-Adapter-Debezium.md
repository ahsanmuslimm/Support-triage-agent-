## Overview

### What This Delivers

S6.2 replaces the MVP event bus with a production-grade distributed event system:

**Before (MVP)**:
- OutboxPoller polls outbox_events table every 1 second
- In-process pub/sub
- No durability if process crashes
- Difficult to replay events

**After (S6.2)**:
- Kafka 4 cluster (3 brokers, KRaft mode, no ZooKeeper)
- Debezium PostgreSQL connector captures CDC (Change Data Capture)
- Protobuf-serialized CloudEvent envelope
- Multi-tenant isolation via partition key = tenant_id
- Event replay capability
- Exactly-once semantics (S6.3 idempotency)

**Key Artifacts:**
- `services/api/src/triage/adapters/event_bus_kafka.py` - Kafka EventBus implementation (350+ lines)
- `services/api/src/triage/adapters/event_bus_factory.py` - Toggle MVP ↔ Kafka
- `tools/debezium/postgres-connector-config.json` - Debezium connector config
- `tools/debezium/pre_migration_check.py` - Pre-deployment validation script
- Docker Compose updates (Kafka cluster, Debezium, Kafka Connect)

### Design Principles

1. **Topic Naming**: "message.ingested" → "triage.message.ingested"
2. **Partition Key**: tenant_id (ensures ordering per tenant)
3. **Serialization**: Protobuf-serialized CloudEvent envelope (S6.1)
4. **Ack Strategy**: acks='all' (wait for all in-sync replicas)
5. **Debezium Integration**: PostgreSQL CDC captures all outbox events automatically
6. **Graceful Cutover**: MVP and Kafka can run in parallel (feature flag)

## Architecture

### Kafka Cluster (KRaft Mode)

```yaml
# docker-compose.yml updates
kafka-broker-1/2/3:
  image: confluentinc/cp-kafka:7.5.0
  environment:
    KAFKA_BROKER_ID: {1,2,3}
    KAFKA_PROCESS_ROLES: broker,controller
    KAFKA_CONTROLLER_QUORUM_VOTERS: 1@...:9092,2@...:9092,3@...:9092
    # No ZooKeeper (KRaft mode)

# Topics (auto-created)
triage.message.ingested
triage.message.classified
triage.action.executed
triage.message.escalated
triage.dlq                   # Dead Letter Queue (S6.3)
```

**KRaft Mode Benefits**:
- Simpler architecture (no ZooKeeper)
- Faster controller elections
- Unified log storage for metadata

### Debezium CDC Pipeline

```
PostgreSQL (outbox_events table)
    ↓
Debezium PostgreSQL Connector
    ↓
CDC Event (INSERT, UPDATE)
    ↓
EventRouter Transform (routes by event_type)
    ↓
Kafka Topics (triage.{event_type})
    ↓
Applications (Consumers) via KafkaEventBus.subscribe()
```

**Key Connectors**:
1. **PostgreSQL Source**: Captures outbox_events WAL
2. **EventRouter Transform**: Routes events to topics by event_type field
3. **Filter Predicate**: Only publishes unpublished events (published_at IS NULL)

### EventBus API

```python
# Publish (Application → Kafka)
bus = KafkaEventBus(bootstrap_servers="...")
await bus.connect()
await bus.publish(
    event_type="message.ingested",
    tenant_id="tenant_1",
    payload=domain_event,  # Protobuf or dict
    aggregate_id="msg_456",
    outbox_event_id="evt_123",  # Reused from OutboxEvent.id (S6.3)
)

# Subscribe (Consumer ← Kafka)
async def handle_event(event_dict):
    print(f"Received: {event_dict['type']}")

await bus.subscribe(
    event_types=["message.ingested", "message.classified"],
    handler=handle_event,
)
```

## Implementation Details

### 1. KafkaEventBus (event_bus_kafka.py)

**Key Methods**:

| Method | Purpose |
|--------|---------|
| `connect()` | Establish producer connection to Kafka brokers |
| `disconnect()` | Graceful shutdown |
| `publish(event_type, tenant_id, payload, ...)` | Publish to Kafka topic |
| `subscribe(event_types, handler)` | Consume from topics with handler callback |
| `_serialize_protobuf(data)` | Convert to Protobuf bytes |
| `_deserialize_protobuf(bytes)` | Convert from Protobuf bytes |
| `_build_cloud_event_dict()` | Wrap domain event in CloudEvent envelope |
| `_send_to_dlq()` | Route failed events to DLQ topic (S6.3) |

**Configuration**:
- `acks='all'`: Wait for all in-sync replicas before acknowledging
- `compression_type='snappy'`: Reduce bandwidth
- `linger_ms=100`: Batch messages for efficiency
- `enable_auto_commit=False`: Explicit offset commit (safer)

### 2. EventBusFactory (event_bus_factory.py)

**Feature Flag**:
```python
# Environment variable: USE_KAFKA_EVENTS (default: "false")
USE_KAFKA = os.getenv("USE_KAFKA_EVENTS", "false").lower() == "true"

# Create appropriate implementation
bus = EventBusFactory.create_event_bus(use_kafka=USE_KAFKA)
# Returns: KafkaEventBus (if true) or OutboxWriter (if false)
```

**Migration Path**:
1. **Phase 1**: Deploy with USE_KAFKA_EVENTS=false (MVP continues)
2. **Phase 2**: Run both MVP and Kafka in parallel, route subset to Kafka
3. **Phase 3**: Switch to USE_KAFKA_EVENTS=true (Kafka handles all events)

### 3. Debezium Connector Config (postgres-connector-config.json)

**Key Settings**:

```json
{
  "connector.class": "io.debezium.connector.postgresql.PostgresConnector",
  "table.include.list": "triage.outbox_events",
  
  "transforms": "outbox,filter",
  "transforms.outbox.type": "io.debezium.transforms.outbox.EventRouter",
  "transforms.outbox.route.by.field": "event_type",
  
  "snapshot.mode": "initial",
  "snapshot.isolation.mode": "read_committed",
  
  "errors.deadletterqueue.topic": "triage.dlq.postgres",
  "errors.log.enable": true
}
```

**Critical Settings** (H1 Fix):
- `snapshot.mode: "initial"`: Take snapshot ONCE on first deployment
- Filter predicate: Only captures unpublished events (published_at IS NULL)
- Pre-migration check (H1 Fix): Validates outbox schema before deployment

## FAQ

**Q: Will Kafka deployment cause downtime?**  
A: No. Feature flag allows MVP and Kafka to run in parallel. Gradual cutover possible.

**Q: What if Kafka cluster fails?**  
A: MVP OutboxPoller continues (Feature flag: USE_KAFKA_EVENTS=false). Rollback <5min.

**Q: How many Kafka brokers do we need?**  
A: Minimum 3 for HA. KRaft mode simplifies without ZooKeeper.

**Q: Can we replay events from Kafka?**  
A: Yes. Consumers can seek to any offset. Combined with S6.3 idempotency = safe replay.
