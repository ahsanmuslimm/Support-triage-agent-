**Sprint:** 1 (Ingestion & Conversation Core)  
**Deliverable:** Zendesk bidirectional webhook integration  
**Effort:** 2 days  
**Dependencies:** S0 (API foundation), S1.1 (Message normalization), S1.2 (Ingestion endpoint)

---

## Overview

The Zendesk webhook receiver accepts signed webhook events from Zendesk, validates authenticity, ingests new comments and ticket status changes, and writes triage outcomes back to Zendesk ticket sidebars.

This enables:
- **Inbound comments** → normalized messages → triage queue
- **Status changes** → conversation state updates
- **Triage outcomes** → written to Zendesk sidebar as internal notes (visible to agents only)
- **Hand-off** → triage resolution + escalation reason + agent assignment

## Technical Specification

### 1. Zendesk Webhook Event Types

Support the following Zendesk webhook events:

| Event | Source | Purpose |
|---|---|---|
| `ticket.created` | New ticket created | Create conversation, ingest initial comment |
| `ticket.comment.created` | New public/private comment | Ingest as message |
| `ticket.status_changed` | Ticket status change (open→pending, etc.) | Update conversation status |
| `ticket.assignee_changed` | Reassignment | Track agent assignment |

### 2. Webhook Signature Verification

**Standard:** Use Zendesk's HMAC-SHA256 signing scheme.

```python
# Pseudo-code
def verify_zendesk_signature(request_body: bytes, signature: str, secret: str) -> bool:
    """Verify Zendesk webhook signature."""
    expected = base64.b64encode(
        hmac.new(
            secret.encode(),
            request_body,
            hashlib.sha256
        ).digest()
    ).decode()
    return hmac.compare_digest(signature, expected)
```

**Headers:**
- `X-Zendesk-Webhook-Signature` — Base64-encoded HMAC-SHA256
- `X-Zendesk-Webhook-Timestamp` — Unix timestamp (reject if >5 minutes old)

**Implementation:**
- Fetch Zendesk signing secret from configuration (tenant-scoped in database or KeyVault)
- Reject if signature doesn't match
- Reject if timestamp is older than 5 minutes (replay protection)
- Log all rejections (auth failure, timestamp skew)

### 4. Event Processing Logic

#### 4.1 `ticket.created`
- Extract `ticket.id`, `description`, `requester_email`, `custom_fields`
- Create conversation if not exists (`channel="zendesk"`, `external_id=ticket.id`)
- Normalize description as initial message
- Ingest via S1.2 endpoint (background task)
- Store `zendesk_ticket_id` in conversation metadata

#### 4.2 `ticket.comment.created`
- Extract `ticket.id`, `body`, `public` flag, `author_id`
- Normalize as message
- If private comment from agent: skip (don't feed back triage)
- If public/requester comment: ingest as message
- Idempotency key: `zendesk_comment_{comment_id}`

#### 4.3 `ticket.status_changed`
- Extract `ticket.id`, `new_status` (open, pending, on_hold, solved, closed)
- Map to conversation status: `open` → triage, `pending` → awaiting_customer, `solved/closed` → resolved
- Update conversation state

#### 4.4 `ticket.assignee_changed`
- Extract `ticket.id`, `new_assignee_id`
- Store agent assignment in conversation metadata
- No immediate action (agent is human, triage already completed)

### 5. Write-Back to Zendesk (Ticket Sidebar)

**Trigger:** When triage completes (outcome = auto-resolved, escalate, route-to-department, etc.)

**Implementation:**
- Call Zendesk API: `POST /api/v2/tickets/{ticket_id}/comments`
- Write internal note (visible to agents only):
  ```
  [TRIAGE AGENT] Classification: {intent}
  Confidence: {confidence}
  Suggested Resolution: {action}
  Reason: {explanation}
  
  Agent Next Steps: {routing_destination}
  ```
- Use ticket_id from conversation metadata

**Idempotency:**
- Store write-back event_id in database
- Don't write twice for same outcome

**Error Handling:**
- If write-back fails (Zendesk API error, auth failure): log and retry via background worker
- Don't fail the triage outcome

### 7. Rate Limiting & Backpressure

- **Webhook endpoint:** 100 req/s per tenant (sliding window)
- **Zendesk API calls:** 50 write-backs/s (batched)
- **Message queue:** If ingestion is slow, buffer in Redis with TTL=1h
- **Dead-letter:** Failed events stored in `webhook_events_dlq` table for manual retry

### 8. Idempotency & Ordering

- **Idempotency key:** `zendesk_{event_id}` (Zendesk provides `id` on all events)
- **Ordering:** Use conversation lock (from S1.4) to serialize comment ingestion per ticket
- **Deduplication:** Check if event_id already in `webhook_events` table
- If duplicate: return 200 OK (idempotent)

### 9. Multi-Tenancy

- **Webhook registration:** Each tenant configures their own Zendesk subdomain + API credentials
- **Signature verification:** Use tenant-scoped signing secret
- **RLS:** Query only conversations for the tenant bound to the Zendesk config
- **Error response:** If tenant not found → 404 (hide that this tenant exists)

### Example: Webhook Receiver

```python
# packages/api/src/triage/ingestion/zendesk.py
import hmac
import hashlib
import base64
from datetime import datetime, timedelta
from typing import Optional
from pydantic import BaseModel

class ZendeskWebhookEvent(BaseModel):
    id: str
    created_at: str
    event_type: str
    data: dict

class ZendeskReceiver:
    def __init__(self, signing_secret: str):
        self.signing_secret = signing_secret
    
    def verify_signature(self, request_body: bytes, signature: str, timestamp: str) -> bool:
        """Verify HMAC-SHA256 signature and timestamp."""
        # Check timestamp (reject if >5 min old)
        event_ts = datetime.fromisoformat(timestamp.replace('Z', '+00:00'))
        if datetime.now(event_ts.tzinfo) - event_ts > timedelta(minutes=5):
            return False
        
        # Verify signature
        expected = base64.b64encode(
            hmac.new(
                self.signing_secret.encode(),
                request_body,
                hashlib.sha256
            ).digest()
        ).decode()
        
        return hmac.compare_digest(signature, expected)
    
    def route_event(self, event: ZendeskWebhookEvent) -> tuple:
        """Route event to appropriate handler."""
        handlers = {
            "ticket.created": "ticket_created_handler",
            "ticket.comment.created": "ticket_comment_handler",
            "ticket.status_changed": "ticket_status_handler",
            "ticket.assignee_changed": "ticket_assignee_handler",
        }
        return handlers.get(event.event_type)
```
