```bash
# 4. Investigation (parallel to rollback):

# - Review recent errors

# 5. Post-incident:
# - Document root cause
# - Fix issue (may take hours)

```

### Rollback Impact

- **RTO (Recovery Time)**: <5 minutes
- **Data Consistency**: Guaranteed (MVP outbox still intact)

## Parity Verification

### Definition

**Parity**: MVP and Kafka process same events, produce same results

**Measurement**:
```python
# For each event type:
mvp_events = get_events_from_mvp_outbox()      # What MVP processed
kafka_events = get_events_from_kafka_topic()   # What Kafka captured

for event_type in ["message.ingested", "message.classified", ...]:
    mvp_count = len([e for e in mvp_events if e.type == event_type])
    kafka_count = len([e for e in kafka_events if e.type == event_type])
    
    divergence = abs(mvp_count - kafka_count) / max(mvp_count, kafka_count)
    
    if divergence > 0.001:  # >0.1%
        alert(f"Divergence: {divergence * 100}% for {event_type}")
```

### Acceptable Divergence

- **<0.1%**: Proceed with cutover
- **0.1%-1%**: Investigate but proceed (known issues)
- **>1%**: Stop cutover, investigate before retry

### Root Causes of Divergence

1. **Clock skew**: MVP timestamp ≠ Kafka timestamp
2. **Duplicate events**: Same event published twice
3. **Lost events**: Event dropped between MVP and Kafka
4. **Malformed events**: Event doesn't deserialize
5. **Race conditions**: Event processing order differs

## FAQ

**Q: Can we fully rollback if Kafka cutover fails?**  
A: Yes. Set KAFKA_TRAFFIC_PERCENTAGE=0, restart. MVP OutboxPoller still running = immediate recovery.

**Q: What if parity divergence keeps appearing?**  
A: Investigate root cause (clock skew, network lag, etc.). Fix and retry cutover week.

**Q: Do we need to run Temporal for S6.1-S6.4?**  
A: No. S6.5 (Temporal) can be integrated later. S6.1-S6.4 provide Kafka + idempotency independently.

**Q: Can we run Phase 1-3 concurrently?**  
A: No. Need sequential validation. Each phase validates before next begins.

**Q: How do we handle pre-existing events in OutboxPoller during cutover?**  
A: Debezium snapshots them (snapshot.mode="initial"). Both MVP and Kafka see them initially. Idempotency (S6.3) ensures once-only processing.
