# S4.1 — Anomaly Detection & Risk Signals

## Overview

The Anomaly Detection & Risk Signals module provides real-time detection of abnormal patterns in customer support metrics and behaviors, enabling proactive intervention before issues escalate. This module processes continuous streams of metrics (ticket volume, response times, sentiment shifts, user activity patterns) and identifies statistically significant deviations that indicate emerging risks: churn acceleration, fraud campaigns, complaint surges, bot activity, or system degradation.

**Business Value:**
- **Proactive Support:** Detect churn signals 24–48 hours before customer disengagement
- **Fraud Prevention:** Identify coordinated bot attacks or account takeover attempts in real-time
- **SLA Protection:** Alert ops teams to metric drifts before they breach SLAs
- **Tenant Isolation:** Per-tenant risk thresholds prevent noise from low-volume accounts masking critical signals

**Fit into Triage Platform:** Anomaly signals feed the triage orchestrator as high-urgency context; when a churn spike is detected, incoming tickets from that cohort are automatically escalated and routed to retention specialists.

## Technical Specification

### Detection Strategy

The module employs a **detector ensemble** combining two complementary algorithms:

1. **EWMA (Exponentially Weighted Moving Average)** — Detects trends and drift
   - Sensitive to gradual shifts in baseline behavior
   - Tracks mean and variance with exponential forgetting (α parameter controls memory horizon)
   - Formula: `μₜ = α·xₜ + (1−α)·μₜ₋₁` where α ∈ [0.01, 0.2]
   - Threshold: `|xₜ − μₜ₋₁| > β·σₜ₋₁` (β typically 2.5–3.0 standard deviations)

2. **Isolation Forest** — Detects point anomalies and multi-dimensional outliers
   - Isolates rare observations by random feature-space splitting
   - Anomaly score: normalized path length in ensemble of isolation trees
   - Requires warm-up (≥500 baseline points) before scoring begins
   - Per-tenant contamination rate (typical 0.05–0.15) sets decision boundary

### Risk Signal Types

| Signal Type | Metric | Trigger |
|---|---|---|
| **churn_spike** | Churn rate (% inactive users/day) | EWMA drift >2σ for 2+ consecutive hours |
| **fraud_pattern** | Bot detection score aggregate | Isolation Forest anomaly score >0.7 |
| **complaint_surge** | Negative sentiment ticket count | Isolation Forest on 24h rolling window |
| **response_delay** | P95 response time (seconds) | EWMA drift + Isolation Forest confirmation |
| **volume_spike** | Tickets ingested per minute | EWMA on 30m sliding window |
| **api_error_rate** | Error count / total requests | EWMA >threshold with severity bucketing |

### Architecture Overview

```
Metrics Stream (Kafka / HTTP ingest)
    ↓
Signal Ingestion Pipeline (buffer + batch)
    ↓
Detector Ensemble (EWMA + Isolation Forest in parallel)
    ↓
Risk Scoring & Aggregation
    ↓
Alert Dispatch (webhook, Slack, PagerDuty integrations)
    ↓
Observability (Prometheus + event logs)
```

**State Management:** EWMA statistics (mean, variance) and Isolation Forest model parameters stored in Redis with tenant-scoped keys and TTL-based eviction of stale data.

## Implementation

### EWMA Detector

**Initialization:**

```python
class EWMADetector:
    def __init__(self, alpha=0.08, threshold_sigma=2.8, warm_up_count=100):
        self.alpha = alpha
        self.threshold_sigma = threshold_sigma
        self.warm_up_count = warm_up_count
        self.count = 0
        self.mean = 0.0
        self.variance = 0.0
        self.is_ready = False
    
    def update(self, value):
        """Update EWMA statistics. Returns (z_score, is_anomaly)."""
        if self.count < self.warm_up_count:
            self.count += 1
            self.mean = (self.mean * (self.count - 1) + value) / self.count
            variance_increment = (value - self.mean) ** 2
            self.variance = (self.variance * (self.count - 1) + variance_increment) / self.count
            return 0.0, False
        
        self.is_ready = True
        prior_mean = self.mean
        prior_std = max(1e-8, self.variance ** 0.5)
        
        # Update EWMA
        self.mean = self.alpha * value + (1 - self.alpha) * self.mean
        delta = value - prior_mean
        self.variance = self.alpha * (delta ** 2) + (1 - self.alpha) * self.variance
        
        z_score = abs(value - prior_mean) / prior_std
        is_anomaly = z_score > self.threshold_sigma
        
        return z_score, is_anomaly
```

### Isolation Forest Detector

**Setup & Scoring:**

```python
from sklearn.ensemble import IsolationForest

class IsolationForestDetector:
    def __init__(self, n_estimators=100, contamination=0.10, random_state=42):
        self.model = IsolationForest(
            n_estimators=n_estimators,
            contamination=contamination,
            random_state=random_state,
            n_jobs=-1
        )
        self.feature_buffer = []
        self.min_samples = 500
        self.is_trained = False
    
    def fit(self, feature_vectors):
        """Train on baseline data."""
        if len(feature_vectors) < self.min_samples:
            return False
        self.model.fit(feature_vectors)
        self.is_trained = True
        return True
    
    def score(self, feature_vector):
        """
        Returns anomaly score [0, 1] where 1 = maximum anomaly.
        """
        if not self.is_trained or len(self.feature_buffer) < 20:
            return 0.0, False
        
        # Normalized anomaly score
        raw_score = self.model.score_samples([feature_vector])[0]
        # Transform to [0, 1] range
        normalized_score = 1.0 / (1.0 + np.exp(raw_score))
        is_anomaly = normalized_score > (1.0 - self.model.contamination)
        
        return normalized_score, is_anomaly
```

### Detector Ensemble

**Orchestration Logic:**

```python
def detect_anomaly(tenant_id, signal_type, value, timestamp):
    """Run ensemble: EWMA first, Isolation Forest for confirmation."""
    
    ewma_detector = load_ewma_detector(tenant_id, signal_type)
    if_detector = load_isolation_forest_detector(tenant_id, signal_type)
    
    # EWMA pass
    z_score, ewma_anomaly = ewma_detector.update(value)
    
    # Isolation Forest pass (if EWMA signals or IF is trained)
    if_score, if_anomaly = 0.0, False
    if if_detector.is_trained:
        feature_vector = build_feature_vector(tenant_id, signal_type, value)
        if_score, if_anomaly = if_detector.score(feature_vector)
    
    # Ensemble decision: require both detectors to agree for high confidence
    is_ensemble_anomaly = ewma_anomaly and if_anomaly
    is_single_anomaly = ewma_anomaly or if_anomaly
    
    confidence = 0.95 if is_ensemble_anomaly else 0.70 if is_single_anomaly else 0.0
    detector_name = "ensemble_confirmed" if is_ensemble_anomaly else ("ewma" if ewma_anomaly else "isolation_forest")
    
    if is_single_anomaly:
        signal = AnomalySignal(
            tenant_id=tenant_id,
            signal_type=signal_type,
            value=value,
            z_score=z_score,
            detector=detector_name,
            confidence=confidence,
            severity=compute_severity(z_score, if_score)
        )
        return signal
    
    return None
```

### Webhook Dispatch & Retries

**Async Dispatch with Exponential Backoff:**

```python
import asyncio
import aiohttp

class AlertDispatcher:
    def __init__(self, max_retries=5, base_backoff=2):
        self.max_retries = max_retries
        self.base_backoff = base_backoff
    
    async def dispatch_alert(self, alert_id, webhook_url, payload, auth_token=None):
        """Send alert to webhook with exponential backoff retry."""
        headers = {"Content-Type": "application/json"}
        if auth_token:
            headers["Authorization"] = f"Bearer {auth_token}"
        
        for attempt in range(self.max_retries):
            try:
                async with aiohttp.ClientSession() as session:
                    async with session.post(
                        webhook_url,
                        json=payload,
                        headers=headers,
                        timeout=10
                    ) as resp:
                        if resp.status in [200, 202]:
                            log_event("alert_delivered", alert_id, resp.status)
                            return True
                        elif resp.status >= 500:
                            # Retryable
                            await asyncio.sleep(self.base_backoff ** attempt)
                        else:
                            # Client error, fail immediately
                            log_event("alert_failed", alert_id, resp.status)
                            return False
            except asyncio.TimeoutError:
                if attempt < self.max_retries - 1:
                    await asyncio.sleep(self.base_backoff ** attempt)
            except Exception as e:
                log_event("alert_dispatch_error", alert_id, str(e))
        
        log_event("alert_max_retries_exceeded", alert_id)
        return False
```

import redis

class ConfigManager:
    def __init__(self, redis_client):
        self.redis = redis_client
        self.cache_ttl = 300  # 5 minutes
    
    @lru_cache(maxsize=1000)
    def get_alert_config(self, tenant_id, signal_type):
        """Cached config retrieval."""
        cache_key = f"config:alert:{tenant_id}:{signal_type}"
        cached = self.redis.get(cache_key)
        
        if cached:
            return json.loads(cached)
        
        # Load from database
        config = db.query(AlertConfig).filter_by(
            tenant_id=tenant_id,

        ).first()
        
        if config:
            self.redis.setex(cache_key, self.cache_ttl, json.dumps(config.to_dict()))

        return None

### Scaling Architecture

**Stateless Workers:**
- Deploy N detection workers (horizontal scaling, no shared state except Redis)
- Each worker: Kafka consumer → detector logic → Redis updates → async webhook dispatch
- No local in-memory state; all EWMA/IF models live in Redis

**Redis Clustering:**
- Use Redis Cluster or Sentinel for HA
- Key partitioning by tenant_id ensures even distribution
- TTL on all anomaly state (24h for EWMA, 7d for IF training data)

**Kafka Partitioning:**
- Topic: `metrics-ingest` — 32 partitions (per-tenant affinity via tenant_id key)
- Topic: `anomalies` — 8 partitions (fan-out to alert dispatch workers)

**Kill Switch:** Set ENABLE_ANOMALY_DETECTION=false to disable all detection and alert dispatch across platform.
